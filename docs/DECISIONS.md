# Design decisions

One row per choice that a teammate or evaluator might question. Add a row in the
same PR that makes the choice. "Why" is the part you say out loud in the viva.

| # | Decision | Why | Alternative rejected | Owner |
|---|---|---|---|---|
| 1 | BFS layered by **boardings**, not by stops | The objective is fewest buses: every leg costs exactly 1, no matter how many stops it crosses | BFS counting stops — optimises the wrong quantity | Role 1 |
| 2 | Hand-written queue (circular array or linked) for the frontier | Course rule: no built-in shortcuts for the core problem; queue is Module 2 and gives us something to explain | `std::queue` / `std::deque` | Role 1 |
| 3 | A route is an **undirected set** of stops | The problem's example boards `R2` at 7 and alights at 6 while `R2 = [3,6,7]`; no direction or timetable data exists | Directed traversal — makes the worked example unsolvable | Role 1 |
| 4 | Index built once in `build_network` | 40,000 appearances; the spec explicitly requires repeated queries without rebuilding | Rebuilding per query — violates the requirement and is O(A) per query extra | Role 1 |
| 5 | Inactive routes filtered **per query** | Closures change between queries; the index must stay reusable | Removing routes and rebuilding — defeats decision 4 | Role 1 |
| 6 | Each route expanded at most once per query (`expanded[]`) | Overlapping services would otherwise be rescanned from every stop; bounds a query to O(A) | Rescan route stops for every reached stop — quadratic on dense networks | Role 1 |
| 7 | `unordered_map<string, vector<int>>` for stop → routes | Average O(1) lookup; hashing is Module 5 content; the interface hides it | Adjacency matrix — 40,000 stops makes it impossible; linear scan — O(A) per lookup | Role 1 |
| 8 | `include/journey.hpp` frozen, one owner per file | Three people (and three AI tools) editing in parallel otherwise conflict constantly | Shared free-for-all editing | Team |
| 9 | Output always says `buses`, exact block format | One less edge case; byte-exact `diff` tests | Pluralisation / free-form output | Role 2 |
| 10 | No tie-breaking between equally short journeys | The spec asks for a minimum, not a specific one; tests assert count + validity | Lexicographically smallest route sequence — extra work, no grading value | Role 3 |
| 11 | C++17, plain `make`, zero dependencies | Runs on any lab machine with g++; nothing to install | CMake/Conan/Boost — setup risk for no benefit | Team |
| 12 | Tests assert **leg count + contract validity**, never one specific path unless it is unique | The spec accepts any optimal journey; a path assertion would fail a valid alternative and turn a green implementation red | Exact-path equality for every case | Role 3 |
| 13 | `journey_is_valid` re-derives validity from the raw route list, not from `find_journey`'s parent links | A validator that trusts the implementation's own bookkeeping agrees with its bugs | Checking the parent chain the search just built | Role 3 |
| 14 | Worst case generated by a deterministic hand-written LCG | Same bytes every run, so a slow perf number is reproducible; stays inside the allowed headers (no `<random>`) | Random seed per run — cannot reproduce a failure | Role 3 |
| 15 | Perf check fails only above **1 s** for 100 queries on 40,000 appearances | Loose on purpose: catches an accidental O(routes × stops) rescan, not machine speed | Tight millisecond thresholds — flaky on lab hardware | Role 3 |
| 16 | `samples/big.txt` is generated by `make gen`, not committed | It is build output; the generator reproduces it byte-for-byte | A ~200 KB fixture that churns whenever the generator changes | Role 3 |
| 17 | The browser UI is a **separate mode** (`--serve`), not a replacement for the CLI | The graded artefact stays byte-exact and the UI cannot regress it; batch mode still runs with no arguments | A web-only program — impossible to grade against `samples/expected1.txt` | UI |
| 18 | Instrumentation lives in `stats.hpp` and one shared BFS function with a nullable stats pointer | The demo and `make test` must run the *same* traversal; a second implementation would be a second source of truth | Re-implement BFS in JS, or recompute layers in the server | Role 1 / UI |
| 19 | Hand-written HTTP and JSON on POSIX sockets | `make` stays dependency-free and offline; the server is one explainable file (~1,100 lines) | `cpp-httplib`, Boost.Beast, Node/Python sidecar | UI |
| 20 | Vanilla JS and SVG, no framework or CDN | A lab machine may have no network; there is no build step, so the UI is just three files | React/Vue via CDN, bundler toolchain | UI |
| 21 | BFS layer edges are reconstructed from `expanded_routes` + `expanded_route_buses` | The search already knows which route reached each layer; sharing that avoids guessing parents in the client | Returning a full parent array (bigger API) or a random tree | UI |
| 22 | Above ~220 stops: sorted grid, one route hue, endpoints-only labels | Force layouts and 400 colours become a hairball at that size; a grid reads as structure and lets the journey stand out | Force layout for all sizes | UI |
| 23 | Closure sweep re-runs the query once per route on the same index | It makes the "repeated queries without rebuilding" requirement visible and answers a real question ("which bus is critical?") | Rebuilding for each closure, or shipping a static list | UI |
| 24 | The JSON reachable list is capped at 2,500 stops; layer **counts** are always exact | Bounds the response on pathological inputs; the legend discloses truncation, so the minimality argument never depends on the cap | Unbounded payload, or silently drawing a subset | UI |
| 25 | Optional batch `[input-file]` in `main.cpp` while rejecting unknown `-` flags with usage on stderr | Lets users run `./build/journey samples/city.txt` without shell redirection while failing fast on CLI typos | Treating `--unknown` as a filename or forcing shell redirection | Role 2 |
| 26 | Route list hover highlights `.route-path.route-hover` purely in CSS/DOM (`setHoveredRoute`) | Keeps map highlighting instant on 400-route networks without firing `/api/journey` or re-running force layout | Re-rendering the full SVG or querying the server on hover | Role 2 |
| 27 | "Run all queries" executes parsed `query` lines sequentially via `/api/journey` (`runAllQueries`) | Reuses the single-threaded server and one built index without adding a new batch HTTP endpoint, and lets the user inspect any row on click | Adding a dedicated `/api/batch` endpoint or firing 100 concurrent requests | Role 2 |
| 28 | Pointer-map pan/pinch with a 10 px touch tap-slop (`state.pointers`) and deferred pointer capture | Prevents minor finger drift on tap from panning the map or swallowing stop `click` events, while supporting two-finger pinch-zoom | Capturing pointer immediately on `pointerdown` with a 4 px threshold | Role 2 |
| 29 | Global `:focus-visible` rings, explicit `<label>`/`aria-labelledby`, `closed` text badge, dashed destination ring, and `--dim: #8a9bb5` | Makes keyboard focus, dialog titles, open/closed routes, origin/destination endpoints, and secondary text accessible without relying on colour alone | Suppressing browser outlines or leaving `#5d6d87` low-contrast labels | Role 2 |
| 30 | Dense-map stop search (`#stopSearch` ARIA combobox + `#focusOverlay` `<g>` layer) | Lets users jump to any stop on 2,000+ dot maps via keyboard (`F`, arrows, `Enter`) and updates only `#focusOverlay` instead of redrawing all SVG nodes | Re-rendering the entire SVG map on stop selection or relying only on `<datalist>` in From/To | Role 2 |
| 31 | A **real BMTC sample** (`samples/bmtc.txt`) alongside the synthetic ones | Real stop names carry the demo; the graph is still ordinary contract input, so the algorithm is unchanged | Synthetic-only samples — safe but forgettable | UI / Role 3 |
| 32 | Busiest 400 route numbers, one direction each, longer pattern | Fits 400 routes and 12,325 appearances; keeps the recognisable services and city coverage | All 4,895 route numbers — exceeds the contract; random 400 — poor coverage | Role 3 |
| 33 | Stop names become tokens; original names live in `bmtc.json` | The frozen grammar splits on whitespace, but the UI should show "Kempegowda Bus Station" | Change the grammar to quoted names — breaks the frozen contract | Role 2 / UI |
| 34 | Routes stay undirected even though GTFS has UP/DOWN patterns | The problem statement explicitly allows riding against the listed order; one name per route fits the contract | Duplicate routes with `_UP`/`_DOWN` — halves unique services | Role 1 |
| 35 | No map tiles or third-party map library; real coordinates + local projection | Works offline and keeps the build dependency-free; attribution is a caption | Leaflet/OSM tiles — network dependency and extra licence surface | UI |
| 36 | Light theme via `:root[data-theme="light"]` CSS variable overrides + `wayfinder.theme.v1` `localStorage` | Shares one stylesheet and SVG export path (`cssVar`) while preserving >= 5.02:1 WCAG AA contrast in both themes | Maintaining a separate light CSS file or duplicating JS colour tables | Role 3 |
| 37 | Opt-in `--threads N` (`std::shared_mutex` around `AppState` + `FdQueue`) and `--log` on stderr in `server.cpp` | Keeps the default `--serve` path single-threaded and deterministic for demos while allowing concurrent reads (`/api/journey`, `/api/impact`, `/api/network`) under `--threads N` | Detaching per-request threads without bounding concurrency or mutating `AppState` unlocked | Role 2 / Role 3 |
| 38 | Merge the printed-map redesign as the visual base and port U4–U12/R8 into it, instead of stacking the redesign on the old UI | One design system is easier to defend than two; every teammate feature still exists, and the demo check proves it end to end. The dark half of U14 is deferred, not deleted: the redesign is light-only until someone writes the dark variable pass | Keeping the old dark UI and dropping the redesign, or maintaining both stylesheets | UI |

| # | Decision | Why | Alternative rejected | Owner |

| 17 | Compact integer stop IDs + `IntQueue` in `find_journey` | Avoids per-stop string copies and extra hash maps during BFS | String-keyed `buses_used` / `parent_*` maps + `StopQueue` of `std::string` | Role 1 |

| 20 | Lexicographical tie-breaking via layer-ranked BFS + in-place merge sort in `src/graph.cpp` | Processes each boarding layer in ascending prefix-rank order so equal-bus ties deterministically pick the lexicographically smallest route sequence | Unordered BFS tie-breaking or `<algorithm>` `std::sort` | Role 1 |

## How to use this in the demo

When an evaluator asks "why did you do X?", answer with the **why** column, then
name the alternative you rejected. That is the difference between "the AI wrote
it" and "we chose it".
